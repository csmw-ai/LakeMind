## 2. 部署流程

```
# Step 1: 生成 .env（1 次输入：API Key）
python scripts/setup.py

# Step 2: 拉取镜像
docker compose --env-file .env pull

# Step 3: 启动 LakeMind
docker compose --env-file .env up -d

# Step 4: 启动 meeting-agent
docker compose --env-file .env -f examples/meeting-agent/docker-compose.yml up -d

# Step 5: 验证
python scripts/health.py
```

- 用户输入项：**1 项**（LLM API Key）
- 需要的工具：**仅 Docker + Python**（不需要 openssl / Node.js / buildx）

## 4. 1 小时目标评估

**未达标。** 总耗时 342 分钟，是 1 小时目标的 5.7 倍。

### 根因分析

| 因素 | 影响 | 可控性 |
|------|------|--------|
| 网络带宽 1-2 MB/s | 10GB 需 ~90 min（理论最优） | 不可控（用户网络） |
| unexpected EOF × 6 次 | 每次中断 + 重传已完成的层 | 不可控（网络稳定性） |
| ray-worker 4.22GB | 单镜像占总量的 40% | 可优化（减小镜像） |

### 脚本本身耗时（排除镜像拉取）

| 步骤 | 耗时 |
|------|------|
| setup.py | 0.4s |
| docker compose up | 47.1s |
| Ray Serve 就绪 | ~3min |
| 健康检查 | <1min |
| **脚本总计** | **~4 min** |

**结论：脚本设计达标，瓶颈是网络带宽。**
