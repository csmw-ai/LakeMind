## 1. 背景与目标

LakeMind 是认知资产存取平台 + 受控 Job Runtime，包含 10 引擎、13 容器、3 MCP、1 ControlCenter、1 meeting-agent。
原始部署流程需 7 步手动操作（含密钥生成、模型下载、镜像构建、profile 激活等），用户反馈"部署一晚上"。

**目标**：

1. 脚本干净简明，名称易懂
2. 执行操作简单，提示输入项不超过 3 项
3. 静静观测，提示清晰命令
4. 1 小时内完整安装并启动全部功能（含 meeting-agent）
5. `scripts/` 只保留几个必要脚本

### 2.2 脚本说明

#### `scripts/setup.py`（64 行）

- **职责**：从 `.env.example` 生成 `.env`，自动生成 `LAKEMIND_MASTER_KEY`（AES-256-GCM）和 `SERVER_API_KEY`（Bearer token），提示用户输入 LLM API Key
- **输入项**：1 项（`Enter your LLM API Key`）
- **耗时**：0.4s
- **输出**：生成 `.env` + 打印后续 4 行命令
- **跨平台**：Python `secrets` 模块生成密钥，不依赖 openssl

```
$ python scripts/setup.py

  LakeMind Setup
  ==============

  Enter your LLM API Key: <用户输入>

  [OK] .env generated
       LAKEMIND_MASTER_KEY = Al37Xh7MGEdhokb/...
       SERVER_API_KEY      = 4fd895c08f006e1e...
       MAAS_API_KEY        = flMZ4lBv...

  Next steps:
    docker compose --env-file .env pull
    docker compose --env-file .env up -d
    docker compose --env-file .env -f examples/meeting-agent/docker-compose.yml up -d
    python scripts/health.py
```

#### `scripts/health.py`（159 行）

- **职责**：检查全部 6 类服务健康状态
- **输入项**：0
- **退出码**：0 = 全部通过，1 = 有失败
- **检查项**：

| 检查类别 | 检查内容 | 方式 |
|----------|----------|------|
| Containers | 13 容器是否 healthy | `docker compose ps --format json` |
| Server API | 10 引擎是否 online | `GET :10823/api/v1/system/health` |
| MCP | 3 个 MCP 端点 | `GET :8401/health`, `:8402/health`, `:8403/health` |
| Ray Serve | asr-app + embedding-app 是否 RUNNING | `docker exec ... serve.status()` |
| Services | ControlCenter / ModelServing / MeetingAgent | HTTP health endpoints |

#### `scripts/download_models.py`（39 行）

- **职责**：离线下载 3 个模型（SenseVoiceSmall ~900MB + fsmn-vad ~5MB + jina-embeddings ~160MB）
- **触发条件**：`setup.py` 检测到模型不存在时自动调用
- **依赖**：`modelscope` + `fastembed`（自动 pip install）

## 3. 部署流程

### 3.1 完整流程（4 行命令 + 1 行验证）

```bash
# 1. 生成 .env（1 次输入：API Key，0.4s）
python scripts/setup.py

# 2. 拉取镜像（10 镜像 ~10.5GB，耗时取决于网络）
docker compose --env-file .env pull

# 3. 启动 LakeMind（12 容器，~47s）
docker compose --env-file .env up -d

# 4. 启动 meeting-agent（1 容器，~2s）
docker compose --env-file .env -f examples/meeting-agent/docker-compose.yml up -d

# 5. 验证（全部通过 = exit 0）
python scripts/health.py
```

### 3.2 用户视角

| 步骤 | 用户操作 | 耗时 |
|------|----------|------|
| 1 | `git clone` + `python scripts/setup.py` + 输入 API Key | 1 min |
| 2 | `docker compose --env-file .env pull`（等待） | 取决于网络 |
| 3 | `docker compose --env-file .env up -d`（等待） | ~1 min |
| 4 | `docker compose --env-file .env -f examples/meeting-agent/docker-compose.yml up -d` | ~2s |
| 5 | `python scripts/health.py`（验证） | <1 min |

**用户输入项：1 项**（LLM API Key）。
**需要的工具：Docker + Python**（不需要 openssl / Node.js / docker buildx）。

### 3.3 二次部署（镜像已缓存）

```bash
docker compose --env-file .env up -d                                          # ~47s
docker compose --env-file .env -f examples/meeting-agent/docker-compose.yml up -d  # ~2s
python scripts/health.py                                                     # <1 min
# 总计 ~1 min
```

## 4. 配置体系

### 4.1 `.env.example`（65 行，全部配置归口）

| 配置组 | 变量 | 默认值 | 用户需改 |
|--------|------|--------|----------|
| 镜像 | `LAKEMIND_REGISTRY` | `ghcr.io/csmw-ai/lakemind` | 否（GHCR public） |
| 镜像 | `LAKEMIND_VERSION` | `latest` | 否 |
| 镜像 | `COMPOSE_PROFILES` | `ray,all` | 否（自动激活所有 profile） |
| 存储 | `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `admin` / `admin123456` | 生产环境需改 |
| 存储 | `PG_PASSWORD` | `lakemind_pass` | 生产环境需改 |
| Ray | `RAY_WORKER_CPUS` | `4` | 按主机 CPU 调整 |
| Ray | `ASR_NUM_REPLICAS` | `1` | 大集群可增加 |
| LLM | `MAAS_BASE_URL` | 华为云 ModelArts | 按需改 |
| LLM | `MAAS_API_KEY` | `<your-llm-api-key>` | **必填**（唯一手动输入） |
| 密钥 | `LAKEMIND_MASTER_KEY` | `<run: openssl rand -base64 32>` | `setup.py` 自动生成 |
| 密钥 | `SERVER_API_KEY` | `<run: openssl rand -hex 32>` | `setup.py` 自动生成 |

### 4.2 关键设计决策

| 决策 | 效果 |
|------|------|
| `COMPOSE_PROFILES=ray,all` 写入 .env.example | 消除 `--profile ray --profile all` 遗漏 |
| GHCR 镜像设为 public | 无需 `docker login` 即可拉取 |
| meeting-agent Dockerfile 多阶段构建 | 无需宿主机 Node.js |
| `ASR_NUM_REPLICAS=1`（默认） | 适配 4 CPU 集群，避免资源耗尽 |
| SeaweedFS 3.80（非 3.101） | 3.101 在 Docker Hub 不存在 |
| 密钥用 Python `secrets` 生成 | 跨平台，不依赖 openssl |

## 12. 总结

### 已完成

- 脚本体系从 6 个核心脚本精简为 3 个（setup.py + health.py + download_models.py）
- 用户输入从 3 项降为 1 项（仅 LLM API Key）

- 部署命令从 7 步降为 4 行

- 3 轮测试全部通过，13 容器 + 10 引擎 + 3 MCP + 2 Ray Serve + 3 服务全绿

### 未完成

- 1 小时目标在当前网络条件下未达标（需 ≥5 MB/s 网络速度）
- 模型 Bundle 镜像未实现（仍需 Python + modelscope 下载）

### 核心结论

**脚本设计已达标**（4 分钟完成部署），**1 小时目标的瓶颈是网络带宽**（10.5GB 镜像拉取）。在 5+ MB/s 网络或镜像已缓存条件下，1 小时目标可达。
